Policies¶

Architecture and the shared interface for action-chunking policies.

PolicyConfig dataclass ¶

PolicyConfig(policy_type: PolicyType, state_dim: int, action_dim: int, chunk_size: int, hidden_dims: tuple[int, ...] = (128, 128))

Store the architecture needed to reconstruct a policy.

This frozen dataclass records values without validating them. Constructors check their policy kind and delegate layer-size checks to the MLP; this is not a comprehensive configuration validator.

Learning rate, runtime dropout probabilities, and flow integration steps belong outside this configuration. Parameters are stored separately in state_dict().

Attributes:

Name Type Description
policy_type PolicyType

Policy family: "mse" for direct prediction or "flow" for flow matching. The factory rejects unknown values.
state_dim int

Number of state features expected per observation.
action_dim int

Number of features in one action.
chunk_size int

Prediction horizon: actions produced per policy prediction.
hidden_dims tuple[int, ...]

Hidden-layer widths in order. An empty tuple produces a single linear layer with no hidden activations or dropout.

BasePolicy ¶

BasePolicy(config: PolicyConfig)

Bases: Module

Define the shared interface for state-conditioned action-chunk policies.

Subclasses implement initialization, loss computation, and action sampling. Use the explicit methods rather than calling the policy as a module: this base class does not implement forward.

State and randomness

  • Architecture lives in config; learned parameters use the inherited PyTorch Module state interface.
  • Loss and sampling methods receive caller-owned generators. Active dropout and stochastic policy operations consume draws; deterministic paths do not.
  • The caller owns normalization, device placement, and train/eval mode.
